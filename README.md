# dsh-sync-tool

`dsh-sync-tool` 是一个 DeepSeek Harness（DSH）插件，把**每一个 DSH 工作区（一个文件夹）同步到你自己的一个 git 远程仓库**，并且把该工作区里的**会话记录**一起搬过去 —— 在另一台电脑上，它们会被还原成可以直接继续聊的**原生会话**。

同步单位是 **DSH 工作区**，不是插件自己维护的目录清单：工作区由 DSH 创建和管理，插件只为每个工作区回答一个问题 —— **「同步到哪个远端仓库」**。填完之后，该工作区里每一轮对话结束都会自动同步。

插件是一个普通的 **bundle 包**，装进某个 profile 就能用；它**不向模型注册任何工具**，不出现在工具列表里，也不会往对话里插入可见消息。

## 特性

- **一个工作区一个同步目标**：填一个远端地址即可，其余字段都有默认值。
- **按文件夹状态自动分两种模式**：还不是仓库的文件夹整个同步；已经是你项目仓库的文件夹**一点不碰**，只把对话送到共享会话仓库。
- **每轮对话结束自动同步**：监听 `turn/end`，默认只同步当前会话所属的那个工作区。
- **双向同步**：提交 → 拉取合并（快进或 rebase）→ 推送；`direction` 支持 `both` / `push` / `pull`。
- **会话归档随仓库走**：规范 JSONL，默认 zstd 压缩，单条超过 `maxBytes` 就跳过。
- **原生还原**：经 DSH 官方的持久化写入路径重建会话，同一个 session id、同一份 header、同一条事件序列。
- **缓存友好**：默认不改写归档里记录的 `cwd`，续聊时历史逐字节相同，命中已有的前缀缓存。
- **设备提示**：来自另一台机器的历史会让模型知道「这段上下文来自别的电脑」，不新增任何界面元素。
- **可移植认领**：仓库里带一份只含机器无关信息的 `.dsh-sync.json`，第二台机器一键接管。
- **安全默认**：已有仓库的工作区默认一个文件都不提交、不推送；凭据只以环境变量注入 git；暂存区出现敏感文件时拒绝自动提交。

## 它同步什么

- **会话记录**（`sessions.enabled` 为真时）：每个工作区一份归档目录，默认 `<工作区目录>/.dsh-sessions/`。
- **整个文件夹**：仅当文件夹本身还不是 git 仓库、且处于「整个文件夹模式」时，插件才会在它里面 `git init`、提交并推送。

```
<工作区目录>/.dsh-sessions/<sessionId>.jsonl.zstd     # 默认，zstd 压缩
<工作区目录>/.dsh-sessions/<sessionId>.jsonl          # compression: none 时
```

> ⚠️ **隐私提醒**：开启会话同步后，**对话内容本身**会进入归档 —— 你的消息、模型的回复、工具调用的参数与输出、以及记录下来的本机绝对路径。它们会**随同 git 提交推送到你为它配置的那个远端仓库**。请按「它会保存你和模型的全部对话」来对待：放私有仓库，不要放公共仓库；远端一旦公开或与他人共享，对话就会一起公开。

**明确不同步的**：

| 项目 | 说明 |
|---|---|
| `node_modules/`、`lib/`、`dist/`、`*.log` | 内置忽略规则：整个文件夹模式下写进该文件夹的 `.gitignore`；只同步对话模式下不产生任何被跟踪的文件 |
| `.credentials.yaml`、`settings.yaml` | 内置忽略规则；且暂存区一旦出现这类文件会**拒绝自动提交**并报错 |
| `.env`（含 `.env.*`）、`.netrc`、`id_rsa` / `id_ed25519` / `id_ecdsa` / `id_dsa` | 命中即拒绝自动提交（`guardSensitive`），不会推上去 |
| 会话的**附件与图片字节** | 归档只含会话记录本身（header + 事件序列），不含媒体文件 |
| 你的凭据值 | 只在拼装 git 命令的瞬间以环境变量注入；不写进 `.git/config`、不落盘、不进命令行参数 |
| 已有仓库工作区的任何文件 | 「只同步对话模式」下，插件的提交范围只含归档目录 |
| 没有填远端的工作区 | 不参与同步，状态里显示「未配置远端」 |

## 两种模式

插件探测文件夹后**自动决定**模式（`mode: auto`），也可以在面板的「高级」里手动指定：

| | **整个文件夹模式** | **只同步对话模式** |
|---|---|---|
| 适用场景 | 文件夹**还不是** git 仓库：DSH 资产、agent 预设、技能、笔记目录 | 文件夹**已经是**一个 git 仓库：你的项目工作区（含「在另一个仓库内部」的文件夹） |
| 远端填什么 | 这个文件夹自己的远端仓库 | 一个**共享会话仓库**（全局 `sessionsRemote`，多个项目共用；也可以为某个工作区单独指定一个） |
| 插件会做什么 | 在文件夹里 `git init`、补 `.gitignore`、`git add -A` 提交、拉取合并、推送；`.dsh-sessions/` 就在文件夹里，随同一次提交一起走 | 把该工作区的归档复制进插件自己的**镜像工作树**（`$DSH_HOME/sync-tool/repos/<hash>/<工作区名>-<短哈希>/`），在镜像上跑同一套 git 序列，合并后再把镜像里的归档合并回本机归档目录 |
| 不会做什么 | 不会自动解决冲突（rebase 失败即中止并保留现场） | **不提交、不推送、不改分支、不改远端、不改任何被跟踪的文件** |
| 对话进哪个仓库 | 该文件夹自己的仓库（可能与文件夹内容同一个仓库） | 共享会话仓库 —— GitHub 上最多多出这一个仓库，而不是每个工作区一个 |
| 归档会不会进项目历史 | —— | 不会：归档路径被写进该仓库私有的 `.git/info/exclude`，不出现在 `git status`、不会被提交 |

「只同步对话模式」是默认行为：探测到文件夹里已经有一个仓库，插件就选它。反过来，用整个文件夹模式去提交一个已有仓库是一个显式的高级选择，见 `commitScope`。

## 环境要求

- DeepSeek Harness，`dsh` 命令可用；宿主侧需要 `settings`、`subprocess`、`sessionPersistence` 服务，工作区归属还需要 `workspaceRegistry`（没有它时退化为按工作目录匹配）。
- `git` ≥ 2.31 —— 凭据通过 `GIT_CONFIG_COUNT` / `GIT_CONFIG_KEY_n` / `GIT_CONFIG_VALUE_n` 注入，git 2.31 起才与 `-c` 等价。
- Node 运行时需提供 `node:zlib` 的 Zstandard 支持（DSH 自身即要求这一点）；`compression: none` 时不需要该能力。
- 一个你自己可写的远程 git 仓库（HTTPS 或 SSH 均可）。

路径比较对 Windows 与 POSIX 分别处理：Windows 下大小写不敏感、分隔符混用也能对上，POSIX 下保持大小写敏感。

## 安装

插件是一个 **DSH bundle 包**：`dsh plugin add` 会把该包追加进 profile 的 bundle 列表，包自带的 patch 层（`cordis.patch.yml`）在合成时插入宿主半边的加载行。**bundle 列表只在 dsh 启动时读取一次，所以安装完必须重启 dsh**；浏览器半边首次出现时还需要刷新页面。包在 `package.json` 里标记为 `private`，未发布到 npm，从源码构建安装即可。

```sh
# 方式一：从源码打包安装（推荐；prepare 脚本会自动构建，无需先装依赖）
npm pack                                              # 生成 dsh-sync-tool-<version>.tgz
dsh plugin --profile <profile> add ./dsh-sync-tool-<version>.tgz
# 然后重启 dsh

# 方式二：直接把仓库目录装进去（开发时用）
npm run build
dsh plugin --profile <profile> add <仓库的绝对路径>

# 卸载
dsh plugin --profile <profile> remove dsh-sync-tool
```

`files` 白名单只含 `lib/*.js` 与 `cordis.patch.yml`；构建把 `src/host/` 拷成 `lib/`，并把 `src/client/index.js` 包一层浏览器侧的工厂函数，所以单独执行 `npm run build` 也可以。`dsh plugin` 把参数转发给 profile 目录里的 pnpm，请使用**绝对路径**避免解析歧义；以目录方式安装时 pnpm 走链接，本包自己的依赖不会被一并安装 —— 若启动时出现模块解析失败，在插件目录执行一次 `npm install`，或改用方式一的 tarball。

## 快速开始

**第一台机器**

1. 安装并**重启 dsh**。启动日志里出现下面这行，说明宿主半边已挂载（也可用 `dsh --profile <profile> --dump-config` 确认配置里多了 `sync-tool` 一行）：

   ```
   [sync-tool] host half loaded (namespaces "sync-tool", "sync-tool-status", sessions -> ...)
   ```

2. 在侧栏打开要同步的那个**工作区**，并往它里面发一句话（空白会话下会话头部是隐藏的）。
3. 点会话头部**右上角的「同步」按钮**，在面板里填入这个工作区的**远程仓库地址**。面板会先说明文件夹的状态，点 **「保存并同步」** 即按模式执行（整个文件夹模式会初始化仓库并推送）。
4. 之后每轮对话结束都会自动同步。界面元素首次出现需要**刷新页面**。

**第二台机器**

1. 把仓库 clone 成本机的工作区目录：`git clone <远端> <工作区目录>`。
2. 在 DSH 里把这个目录打开为工作区，安装同一个插件并重启 dsh。
3. 如果这个文件夹已被第一台机器同步过，面板会显示「这个文件夹已由另一台机器同步过（远端 …）」和 **[ 启用 ]** —— 点一下就等于填好了远端；没有这行提示时手工填入远端即可。
4. 触发一次同步，`.dsh-sessions/` 里的会话会被还原成本机原生会话，在会话列表里打开就能接着聊。

**让两台机器的工作区路径一致**（同样的挂载点或同样的家目录结构）最省事：会话能正确归入工作区、工具的相对路径可用、前缀缓存也最容易命中。两台机器的 `sessions.compression` 要一致，也别把 `.dsh-sessions/` 加进忽略规则，否则归档不会随提交走。

## 界面

### 会话头部右上角的「同步」按钮（主入口）

按钮显示一个分支图标、一个状态点和一个状态词（待同步／同步中／已同步／冲突／错误），悬停提示为 `同步：<工作区名> · <状态词>（<完整路径>）`。点开是一个锚定面板（点面板外部或按 Esc 关闭）：

| 面板区域 | 内容 |
|---|---|
| 标题行 | 工作区名（文件夹名）+ 可点击复制的完整路径 + 关闭按钮 |
| 认领提示 | 这个文件夹已被另一台机器同步过时出现，显示对方的远端，并提供 **[ 启用 ]** |
| 文件夹状态 | 三种情形之一：**还不是 git 仓库**（提示填一个远端后会在文件夹里 init、提交并推送，含 `.dsh-sessions/`）；**已是一个 git 仓库**（显示远端、当前分支、未提交文件数，并承诺「插件不会动这个仓库的文件、分支和提交。它只把这里的对话记录同步到你的会话仓库。」）；**在另一个 git 仓库内部**（显示仓库根，并说明不会在这里建独立仓库） |
| 远端输入框 | 文件夹不是仓库时标签是「远程仓库」，已是仓库时是「会话仓库」；后者在全局配了共享会话仓库时会提示「留空则用共享会话仓库：…」 |
| 按钮 | **保存并同步**（写入配置并立即跑一次）、**立即同步**、**取消同步**（从配置里移除这一项） |
| 最近结果 | 状态点 + `状态 · 多久以前 · HEAD <短 sha> · ↑领先 ↓落后`，下面一行是失败原因或本次摘要 |
| `▸ 高级` | 模式（自动／整个文件夹／只同步对话）、分支、方向（双向／仅 push／仅 pull）、凭据引用、提交范围（整个文件夹／只提交 .dsh-sessions）；「已是仓库」同时选了「整个文件夹」时显示警告：**如果这个仓库是公开的或与别人共享，你的对话内容会一起被推送。** |

按钮注册在会话头部右对齐的 utilities 座位，排在该行最右。两个已知限制：**空白会话（还没发第一句）时整条会话头部被框架隐藏，按钮不会出现**；当前会话没有可确定的工作区时按钮不渲染。

### Plugins 卡片（兜底入口 + 全局总览）

**设置 → Plugins → Plugin configuration** 里的「工作区 Git 同步」卡片：

| 区域 | 内容 |
|---|---|
| 全局开关 | 启用插件、每轮对话后同步、启动时同步、每轮同步全部工作区，以及防抖毫秒数 |
| 共享会话仓库 | 填 `sessionsRemote`；下方说明「已有自己 git 仓库的工作区，对话会集中镜像到这个仓库，插件不会动项目仓库」 |
| 已配置工作区 | 每个工作区一行：状态点、名称、模式标签、完整路径、`HEAD`、`↑领先 ↓落后`、最近时间，以及 **同步** 与 **移除** 按钮 |
| DSH 工作区总览 | 把 DSH 当前工作区逐个列出，标注「已配置同步」或「未配置同步」 |
| 同步状态 | 空闲还是同步进行中、最后更新时间，以及最近 10 条同步历史 |

卡片是**空白会话下唯一的配置入口**，也是不挑会话的全局总览；它和面板读写同一份配置。

## 每轮同步的行为与时序

- **触发**：会话事件 `turn/end`。
- **范围**：默认只同步**当前会话所属的那个工作区**；会话不属于任何已配置工作区时跳过，除非打开「每轮同步全部工作区」。
- **合并**：`debounceMs` 窗口内多次轮次结束会合并成一次同步；全局同一时刻只跑一个 git 序列，后来的请求排队等待。
- **不阻塞对话**：监听器在轮次提交之后触发、异常被吞掉，同步再慢再失败也不会拖慢或打断对话。

**整个文件夹模式的单次顺序**：

1. 把该工作区的配置写成 `.dsh-sync.json`，让仓库自描述。
2. **【导出会话】** 把该工作区范围内的会话写进 `.dsh-sessions/` —— 必须在提交之前，这样这次提交就能把归档一起发布出去。
3. 识别仓库：`git rev-parse --show-toplevel`；不是仓库则 `git init -b <branch>`；位于**另一个**仓库内部时按 `nestedRepos`（默认 `refuse`）拒绝操作。
4. 对齐 `origin`：没有就 `remote add`，地址不同就 `remote set-url`。
5. 提交本地变更：有变更时先补 `.gitignore`（内置规则 + 该工作区的 `extraIgnores`，只追加缺失的行），再 `git add -A`，用提交信息模板 `git commit --no-verify`。暂存区命中敏感文件则拒绝提交并把该工作区标记为错误。
6. 整合远端：`git fetch --prune origin`；远端有分支而本地还没有提交时检出远端分支；仅远端领先时 `git merge --ff-only`；双方都有新提交时 `git pull --rebase --autostash`。
7. **【导入会话】** 读 `.dsh-sessions/` —— 必须在合并之后，这样才看得到另一台机器刚发布的内容。
8. 推送：`git push -u origin <branch>`（`direction: pull` 时跳过）。
9. 推送后重新读取 ahead/behind 并发布状态，保证你看到的是当前真实值。

**只同步对话模式**把同一套 git 序列跑在插件自己的镜像工作树上：先把各工作区的归档复制进镜像，在镜像里提交／合并／推送，合并完成后把镜像里的归档合并回本机归档目录，再走同一套会话导入逻辑。项目仓库本身只被读取（探测远端、分支、未提交文件数），以及被写入一条 `.git/info/exclude` 规则来隐藏归档目录。

**冲突处理**：rebase 失败时立即 `git rebase --abort` 复原，工作区保持你原本的样子，该工作区被标记为 `conflict`，详情里带 git 的原始报错。插件**不会自动解决冲突**，也不会改动你的文件；手工处理完之后，下一次触发会重试。

**提交身份**：优先使用本机自身的 git 身份，永不被覆盖。只有当 git 因缺少身份拒绝提交时，才用 `commitIdentity` 配置的身份或派生的 `dsh-sync@<主机名>` 重试一次，并在状态里注明用了回退身份。

## 配置项

面板和卡片能改的字段直接编辑；其余字段写在 profile 的 `cordis.patch.yml` 中该行的 `config` 下，或写进 `$DSH_HOME/settings.yaml` 的 `sync-tool` 段。配置分层为 **schema 默认值 → 组合行的 `config` → 用户设置文档**，界面写入的是用户层。

### 顶层

| 字段 | 默认值 | 含义 |
|---|---|---|
| `enabled` | `true` | 总开关，关掉后不做任何自动同步 |
| `syncOnTurnEnd` | `true` | 每轮对话结束后同步 |
| `syncOnStartup` | `false` | 宿主启动时对所有启用的工作区跑一次 |
| `syncAllOnTurnEnd` | `false` | 每轮同步全部启用工作区；关闭时只同步当前会话所属的那个 |
| `debounceMs` | `5000` | 轮次边界的合并窗口（毫秒） |
| `commitMessageTemplate` | `dsh-sync: {host} {time} (turn {turn})` | 提交信息模板，`{host}` `{time}` `{turn}` 会被替换 |
| `commitIdentity` | `{ name: "", email: "" }` | **仅当**本机没有 git 身份时使用的提交身份；留空则回退到 `dsh-sync@<主机名>` |
| `historyLimit` | `20` | 状态文档保留的历史条数 |
| `sessionsRemote` | `""` | 共享会话仓库；「只同步对话模式」的工作区默认镜像到这里 |
| `sessionsRoot` | `""` | 镜像工作树的存放根目录；留空则用 `$DSH_HOME/sync-tool/repos` |
| `sessions` | 见下表 | 会话记录设置，所有工作区共用 |
| `workspaces` | `[]` | 工作区配置列表 |
| `request` | `{ token: 0, path: "", kind: "none", at: 0 }` | 界面 → 宿主的命令通道：每次请求把 `token` 加一，`kind` 为 `sync` / `import` / `probe`，`path` 为空表示全部启用的工作区 |

### `workspaces[]` 中的单项

| 字段 | 默认值 | 含义 |
|---|---|---|
| `path` | 必填 | 本机绝对路径，同时是这一项的标识 |
| `title` | `""` | 显示名；留空时用目录名 |
| `mode` | `auto` | `auto` 按文件夹判定 / `folder` 整个文件夹 / `sessions` 只同步对话 |
| `remote` | `""` | `folder` 模式的远端仓库；`sessions` 模式下留空表示用全局 `sessionsRemote`，填了就为这个工作区单独指定一个会话仓库 |
| `branch` | `main` | 跟踪的远端分支 |
| `credentialRef` | `""` | 凭据名，经 DSH 的凭据服务解析；留空则用系统 git 凭据 |
| `direction` | `both` | `both` 先拉再推 / `push` 只推 / `pull` 只拉 |
| `enabled` | `true` | 是否参与自动同步 |
| `autoCommit` | `true` | 同步前自动提交本地变更 |
| `commitScope` | `all` | 自动提交可以包含哪些路径：`all` 整个文件夹 / `archive` 只提交归档目录（面板对「已是仓库」的文件夹保存时写成 `archive`） |
| `extraIgnores` | `[]` | 追加进该目录 `.gitignore` 的忽略规则 |
| `guardSensitive` | `true` | 暂存区出现敏感文件时拒绝自动提交 |
| `nestedRepos` | `refuse` | 文件夹位于另一个 git 仓库内部时：`refuse` 拒绝操作 / `init` 在文件夹里建立独立仓库（会在父仓库留下未跟踪的 `.git`） |

### `sessions`

| 字段 | 默认值 | 含义 |
|---|---|---|
| `enabled` | `true` | 是否同步会话记录 |
| `dir` | `.dsh-sessions` | 存放归档的子目录名 |
| `compression` | `zstd` | 归档编码：`zstd` 紧凑 / `none` 出可读、可 diff 的明文 |
| `includeDescendants` | `false` | 是否包含工作目录在该工作区**子目录**里的会话（DSH 会给子目录另建工作区，所以默认关） |
| `maxSessions` | `200` | 每个工作区最多同步多少条最新的在范围内会话 |
| `maxBytes` | `0` | 单条归档的字节上限，超出则跳过；`0` 表示不限 |
| `cwdPolicy` | `keep` | 导入时如何处理本机不存在的记录工作目录：`keep` / `auto` / `area` |
| `hintOnDeviceSwitch` | `true` | 是否给模型注入「这段历史来自另一台电脑」的提示 |
| `statePath` | `""` | 机器本地记账文件；留空则用 `$DSH_HOME/sync-tool/sessions.json` |

## 会话记录

**归档格式**：每条会话一个文件，内容是**规范 JSONL**（UTF-8，LF 换行）—— 第一行是 DSH 自身的物理 header 行（键白名单与键序一致，可选字段缺省即省略、不写 `null`），之后每行一个逻辑事件，`seq` 严格连续。默认用 `node:zlib` 的 zstd 压成 `.jsonl.zstd`；`compression: none` 时它是一份可以 diff、可以 review 的明文。

```
{"type":"session","version":3,"id":"...","createdAt":...,"cwd":"...","isSeeded":false,"delegationDepth":0,"agentPreset":"standard"}
{"type":"user/message","seq":0,"time":...,"data":{...},"surfaceOp":"append"}
{"type":"tool/call","seq":1,"time":...,"data":{...}}
```

一条会话属于某个工作区，当且仅当：DSH 把该会话记为这个工作区的成员；或它的 header `cwd` 等于该工作区目录（`includeDescendants` 为真时含子目录）；或**由该工作区导入过**（否则在这台机器上对它做的续聊永远发布不回去）。每轮导出取最多 `maxSessions` 条最新的在范围内会话，超出部分在状态里说明。

**导入是「原生会话」**：不走字节拷贝，而是通过 DSH 的会话持久化契约 `create` → `append` → `flush` → `close` 重建 —— 物理文件名与编码代际由本机后端自己决定，所以得到的是**一等公民**的本地会话：可列举、可 `stat`、可打开、可继续聊，session id、header、每条事件的 `seq` / `time` / 载荷都与归档逐条一致。fork（seed）出来的会话，其继承切点从归档里 `session/end-seed` 事件的 `seq` 反推，推不出来就报错跳过，绝不猜。导入前还会校验文件名与 header 里的 id 一致、归档格式版本（当前 v3）受支持、后缀与配置的 `compression` 一致；任何一条不满足都只记一条说明并跳过，**不会半途写入**。

**缓存与 `cwdPolicy`**：命中已有的前缀缓存需要**重建出的历史、当前的 envelope（系统提示、工作目录、工具表）和模型路由都一致**，插件保证其中的历史部分。工作目录是另一半：DSH 的预设会把 `{{cwd}}` 渲染进系统提示，而系统提示位于 surface 的节点 0 —— 一旦改写 `cwd`，节点 0 就被替换，**前缀缓存从第 0 个 token 起失效**。

| `cwdPolicy` | 行为 | 影响 |
|---|---|---|
| `keep`（默认） | 原样保留归档里记录的工作目录，即使它在本机不存在 | 历史与 envelope 都不变，缓存最容易被命中；代价是这台机器上该路径可能真的不存在 |
| `auto` | 记录的工作目录在本机存在就保留，不存在则改写为本机的工作区路径 | 兼顾可用性；被改写时缓存会失效 |
| `area` | 一律改写为本机的工作区路径 | 最本地化；总是改写 |

**想让两台机器都稳，就让同样的工作区用同一个绝对路径**并保持默认的 `keep`：会话能照常归入工作区，工具的相对路径可用，缓存前缀也一致。路径不一致的会话在侧栏里会落到「未分组」，以不存在的工作目录为基准的工具也会自己失败 —— 这是路径不一致的代价，插件消不掉。

**冲突如何处理**：如果两台机器**离线各自续聊了同一条会话**（历史真正分叉），插件不做任何取舍：本机正在使用的那条保持原样、不动一个事件；归档里的远端分支与本机分支分别另存为 `<工作区目录>/.dsh-sessions/conflicts/<会话id>.<归档mtime>.remote.jsonl` 与 `<会话id>.<归档mtime>.<主机名>.local.jsonl`（文件名稳定，重跑不会重复产生）；该工作区的状态里报会话冲突，并且这个判定会被记住，直到冲突被真正解决。其余情况都是自动的：归档比本地长且本地历史是它的前缀，就只追加缺失的尾部；本地更长则不动本地，由导出侧在两边一致后发布本机的续聊；两边完全一致时零读盘跳过。

**模型可见的设备提示**：打开一条从别的机器同步过来的会话时，插件通过系统提示的**运行上下文通道**追加一小段提示，告诉模型这段历史是在另一台电脑上产生的，里面记录的绝对路径与工具输出都只是历史，动手前先确认路径是否存在，并给出同步副本所在的归档目录。这段文字并进每个会话本来就有的「当前运行上下文」条目中，**不新增界面元素、不改动系统提示本身，因此已缓存的前缀逐字节不变**；它只对**由本机导入过的**会话出现，本机自己开的会话完全不受影响，用 `sessions.hintOnDeviceSwitch: false` 可以关掉。

**记账与状态**：机器本地记账文件（默认 `$DSH_HOME/sync-tool/sessions.json`，不随仓库走）记录每条会话上次导出的指纹、每条归档上次观察到的指纹（避免重复读盘），以及哪条会话从哪台机器导入。文件损坏或丢失只会让下一次同步多读一遍，不会出错。同步时状态详情里会出现这样的片段：`会话↑N`（导出 N 条）、`会话↓M`（新建 M 条）、`会话并入M`（追加尾部）、`会话冲突K`、`会话失败K`；该工作区还没有归档目录时会直接说明。

## 常见问题

| 现象 | 处理 |
|---|---|
| 右上角按钮不出现 | 空白会话（还没发第一句）时框架隐藏整条会话头部，这是预期行为 —— 用 Plugins 卡片配置，或先往这个工作区发一句话。另外确认安装后**重启了 dsh**（bundle 只在启动时读一次）并刷新了页面 |
| 状态显示「不可用」 | 宿主半边没有加载：用 `dsh --profile <profile> --dump-config` 确认有 `sync-tool` 行，然后重启 dsh 并刷新页面 |
| 某个工作区一直是「错误」 | 面板或卡片里该工作区的详情就是原因，里面带 git 的原始输出 |
| 推送失败 | 详情里有 git 的 stderr；据此判断是远端地址、网络还是凭据问题 |
| 显示「冲突」 | 本地与远端改了同一处，rebase 已中止、你的文件没有被改动；手工处理完后下一次同步会重试 |
| 会话没同步过去 | 检查 `sessions.enabled`、该会话的 `cwd` 是否在该工作区（或打开 `includeDescendants`）、归档是否被忽略规则挡住、远端是否收到了提交；「只同步对话模式」下还要确认 `sessionsRemote`（或该工作区的 `remote`）已填 |
| 整个文件夹的内容没同步 | 文件夹已经是 git 仓库时默认走「只同步对话模式」，插件不会提交你的文件；需要连文件夹一起提交时，在面板「高级」里把模式改成「整个文件夹」，并注意公开仓库的警告 |
| 提示找不到模块 / `Cannot find module` | 以目录方式安装不会装本包依赖；在插件目录执行 `npm install`，或改用 tarball 安装 |
| 改了代码不生效 | 宿主半边改动需要重启 dsh；浏览器半边改动需重新 `npm run build` 后刷新页面 |
| 状态一直停在「同步中」 | 进程在同步途中退出了（一次性任务模式会这样）；持续运行的会话不受影响 |

## 开发与测试

```sh
npm run build              # 构建：宿主半边到 lib/*.js，浏览器半边到 lib/client.js
npm test                   # 全部单元与集成测试（node:test）
npm run test:sessions-e2e  # 会话同步的真后端端到端校验
```

`npm test` 由 9 个测试文件组成，当前共 **102 项**。

`test:sessions-e2e` 驱动 DSH 自己的包（`@deepseek-ai/dsh-session-persistence-jsonl` 与提示词注册表），验证四件事：插件写出的规范文本与后端未压缩时写出的文本逐行一致；从一个会话根导出的会话能在另一个根里以同样的 id、header 和事件序列重建；重建出来的会话在那里是一等公民（可列举、可 `stat`、读回内容一致）；设备提示能被真实的提示词注册表接受、渲染进运行上下文快照，而对本机自己的会话完全不出现。它需要一个装有 DSH 官方 `@deepseek-ai/*` 包的 profile 根目录：

```sh
node scripts/e2e-sessions.mjs [profile-root]
# 省略时依次取 $DSH_PROFILE_ROOT、$DSH_HOME/profiles
```

该脚本全程使用临时目录，不会碰你机器上真实的会话存储。

代码分为两半：`src/host/`（`index.js` 宿主入口与轮次钩子、`contract.js` 配置/状态/probe 契约、`workspaces.js` 工作区解析与分组、`mirror.js` 会话镜像、`git.js` git 引擎、`sessions.js` 会话归档引擎、`portable.js` 可移植清单、`notice.js` 设备提示）与 `src/client/index.js`（右上角按钮与面板、Plugins 卡片）。浏览器半边必须是客户端模块表要求的惰性 CJS 闭包工厂（`window.__ModuleLoader__.load({ id, factory })`），由 `scripts/build.mjs` 生成；React 与 UI 组件通过工厂注入的 `require` 取得，不允许跨插件值导入。
